# Shizuku로 불러오기·폴더 편집 / 안 될 때 PC ADB

## 폰에서 쓰는 기본 흐름

1. **Home Up → 백업과 복구 → 즉시**에서 최신 백업을 만듭니다. 자동 백업 주기를 바꿀 필요는 없습니다.
2. Shizuku를 실행합니다. 비루트 기기에서는 개발자 옵션의 무선 디버깅 연결 또는 PC로 시작합니다. [공식 설정 설명](https://shizuku.rikka.app/guide/setup/).
3. **One UI 폴더 정리 → Shizuku로 백업 불러오기**를 누르고 권한을 허용합니다. 최신순 목록에서 방금 만든 원본을 선택합니다.
4. 현재 폴더가 기본 분류안으로 열립니다. 앱을 누르면 다른 폴더 또는 새 폴더로 옮길 수 있습니다. 검색·폴더 필터를 함께 쓸 수 있습니다.
5. **폴더 관리**에서 이름을 바꾸거나 다른 폴더로 합칩니다. **미분류만 추천**은 이미 정리한 폴더를 건드리지 않고, 기기의 앱 카테고리로 미분류만 나눕니다. 알 수 없는 앱은 기타입니다.
6. 분류안은 앱 내부에 자동 저장됩니다. **분류안 저장/불러오기**로 개인 JSON 사본을 만들 수도 있습니다. 다른 원본 해시의 분류안은 거부합니다.
7. **Home Up에 적용 준비 → 새 파일 준비**를 누릅니다. 원본과 해시가 여전히 같고 보호 영역이 같을 때만 새로운 이름의 EXML과 존재하는 동반 파일을 추가합니다. 원본은 덮어쓰지 않습니다.
8. **Home Up 열기**를 누르고 복원 목록에서 새 파일을 선택합니다. 이 앱은 마지막 복원 버튼을 누르지 않습니다.

폴더당 최소 2개 앱이 필요합니다. 하나만 남은 폴더는 **폴더 관리 → 다른 폴더로 모두 합치기**로 정리하세요. 빈 폴더는 앱 이동 시 제거됩니다. 폴더 밖 단독 앱과 숨긴 앱 처리 등은 아직 지원하지 않습니다.

## 권한과 범위

- Shizuku는 **파일 복사에만** 사용합니다. 삼성 서명 권한을 얻거나 런처 DB를 수정하는 방식이 아닙니다.
- 비루트 ADB shell 모드(UID 2000)만 지원합니다. 루트 모드를 요구하지 않으며 루트 서비스로 작업하지 않습니다.
- 앱의 요청 권한은 Shizuku API 권한 하나입니다. 인터넷·전체 파일 접근·삼성 런처 권한은 요청하지 않습니다.
- 파일 서비스는 고정 Home Up 백업 경로의 13자리 숫자 EXML만 읽고, 검증된 새 파일만 추가합니다. 임의 명령 실행/범용 파일 접근 API를 노출하지 않습니다.
- 원본과 분류안은 앱 내부 저장소에 보관합니다. 앱 삭제 시 사라지므로 필요한 원본 사본은 별도로 보관하세요.
- **연결 종료** 또는 Home Up 열기에서 이 앱의 Shizuku 파일 서비스를 종료합니다. Shizuku 서버 자체는 중단하지 않습니다.
- 현재 개인 프로필(user 0)과 시험한 Home Up 형식에 한정합니다. 삼성 보안 폴더·업무 프로필·다른 제조사 런처는 지원 대상으로 검증하지 않았습니다.

## Shizuku가 안 될 때 확인할 것

- 설치만 되어 있고 실행 중이 아닌가요? 재부팅 후에는 Shizuku를 다시 시작해야 할 수 있습니다.
- 앱 권한을 거부했나요? Shizuku의 허용 앱에서 권한을 확인하세요. 앱이 거부 상태에서 강제로 권한을 얻지는 않습니다.
- 파일 서비스 연결/폴더 읽기가 실패하면 **ADB 대안**을 사용합니다. 전체 파일 접근 권한이나 파일 선택기를 반복해서 요청하지 않습니다. 최신 Android의 `Android/data` 제한은 그 권한으로 해결되지 않습니다.
- 원본 해시가 달라지면 덮어쓰지 말고 새 백업을 다시 불러오세요.
- Home Up에서 목록이 갱신되지 않으면 화면을 나갔다 다시 들어오세요. 원본을 삭제하거나 런처 데이터를 지우지 마세요.

## PC ADB 대안 (Shizuku 불필요)

PC에 Python 3.9+와 Android platform-tools(`adb`)가 필요합니다. 휴대폰에서 USB 디버깅 연결을 **직접 승인**하거나 무선 ADB를 페어링합니다. 특정 주소나 기기 일련번호를 저장소에 넣지 않습니다.

```sh
adb devices -l
# 출력에서 대상 기기를 확인한 뒤 명령의 SERIAL을 정확히 교체하세요.
python3 tools/adb_backups.py list --serial SERIAL
python3 tools/adb_backups.py pull --serial SERIAL --output private/original.exml
```

출력의 `source_name`은 나중에 그대로 써야 합니다. 기본은 이름순 최신 파일이며, 특정 원본을 고르려면 `pull --name SOURCE_FILENAME.exml`을 지정합니다. 원본과 해시를 검증하며 기존 로컬 파일은 덮어쓰지 않습니다.

폰의 편집 UI를 쓰려면 원본의 사본을 Download에 넣습니다. **개인 앱 목록과 바로가기가 담긴 민감한 파일**입니다. 공유·공개 저장소에 올리지 마세요.

```sh
adb -s SERIAL push private/original.exml /sdcard/Download/oneui-original.exml
```

앱의 **파일 불러오기**에서 `oneui-original.exml`을 선택하고 폴더를 편집한 뒤 **새 EXML 저장**으로 Download에 저장합니다. 실제 생성된 출력 파일명을 확인하고 PC로 가져옵니다.

```sh
adb -s SERIAL pull /sdcard/Download/EDITED_FILENAME.exml private/edited.exml
python3 tools/adb_backups.py stage --serial SERIAL \
  --source-name SOURCE_FILENAME.exml \
  --source private/original.exml --edited private/edited.exml
```

`stage`는 원본의 기기 해시, 편집 파일의 정확한 앱 구성·페이지·메타데이터, 앱스 외 모든 바이트, 전송 후 해시를 검사합니다. 새 이름이 이미 있으면 거부합니다. 존재하는 `_front.exml`과 미리보기 PNG만 새 이름으로 복사하고 검증합니다. 원본은 덮어쓰지 않으며 런처를 복원하지 않습니다.

그다음 Home Up에서 새 백업을 직접 선택해 복원합니다. 완료 뒤 Download에 임시로 둔 정확한 원본/출력 사본은 필요에 따라 정리하고, 별도 원본은 롤백용으로 남기세요.

PC에서만 분류안을 편집하려면 기존 `oneui_folders.py`와 JSON 분류안을 사용해도 됩니다. APK 편집 로직과 PC 변환기의 XML 직렬화 모양은 달라도, 동일한 보호 영역·컴포넌트·메타데이터 계약을 검사합니다.

## 복원 전후 주의

**Home Up은 전체 레이아웃을 복원합니다.** 파일에서 앱스만 바꿨다고 모든 버전의 런처 동작을 보장할 수 없습니다. 방금 만든 원본을 보관하고 홈·도크·위젯과 실제 폴더를 확인하세요. 포맷·숨긴 앱·격자가 미지원이면 앱이 중단하는 것이 정상입니다. 이때 강제로 복원을 진행하지 마세요.
