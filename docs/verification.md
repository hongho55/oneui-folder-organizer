# 검증 기록과 아직 해결하지 못한 부분

아래는 익명화한 실제 실행 결과입니다. 원본 백업·설치 앱 목록·계정/기기 주소·개인 화면은 공개하지 않습니다. 정적 분석과 실행 증거를 구분합니다.

## 1. EXML 편집과 실제 순정 폴더 복원

시험 범위: Galaxy S26 Ultra 국내판 / One UI 9 / Android 17 / Home Up 18.0.00.36.

- 새 원본 백업을 PC로 읽고 `appOrder` 구간만 바꾼 사본을 생성했습니다.
- 수정 파일 외부의 모든 바이트가 원본과 같음을 확인했습니다.
- 원본과 수정 사본을 별도 파일로 보관하고 Home Up 목록에서 수정 사본을 확인한 뒤 **네이티브 복원 확인 버튼**을 눌렀습니다.
- 복원 후 실제 런처에서 다시 생성한 백업과 대조했습니다: 앱 284개, 폴더 21개, 컴포넌트·폴더 이름·구성·순서 일치, 중복·누락 없음.
- 실제 앱스 화면에서 21개 폴더 이름을 확인하고 대표 폴더 하나를 열어 9개 앱을 확인했습니다.
- 홈 배치·바로가기 대상/제목/좌표·도크·위젯 4개 호스트/제공자 ID를 대조했습니다.

이는 **PC ADB 파일 전송 + Home Up 직접 복원** 경로의 실행 결과입니다. APK 단독 실현을 의미하지 않습니다. 공개 Python 변환기도 동일한 비공개 실제 입력으로 오프라인 회귀 검증하지만, 원본 데이터는 배포하지 않습니다.

### 원시 XML 비교 시 주의한 차이

복원 뒤 내보낸 XML에는 홈의 deep shortcut 인라인 아이콘 속성이 빠졌습니다. 다른 홈 속성과 대상/좌표는 같았고 실제 화면에서 원래 아이콘이 보이는 것을 따로 확인했습니다. 따라서 "복원 후 홈 XML 전체가 바이트 단위로 동일했다"고 주장하지 않습니다.

DeX 앱스에는 이전 액티비티 이름 9개가 현재 이름으로 갱신되고 숨긴 음성검색 항목 하나가 추가됐습니다. 176개 표시 앱의 패키지 순서·페이지는 유지됐습니다. DeX 원시 데이터가 전혀 안 바뀌었다는 주장 역시 하지 않습니다.

## 2. 권한 없는 일반 APK의 파일 입출력

시험 앱은 API 35를 타깃으로 하고 저장소·인터넷·Shizuku 등 어떤 권한도 요청하지 않습니다. 실기기 실행에서 앱 자체 UID와 요청 권한 없음, 전체 파일 접근 없음 상태를 읽었습니다.

- 가상 파일을 시스템 파일 선택기로 Download에 저장했습니다.
- 앱이 저장 파일을 다시 읽어 원본과 SHA-256 및 바이트 전체가 같은지 확인했습니다.
- 그 파일을 시스템 선택기로 다시 선택해 읽었습니다. 읽기·쓰기 왕복 성공입니다.
- Home Up `.AutoBackup` 디렉터리의 직접 조회는 앱 자체 UID에서 거부됐습니다.
- Home Up 디렉터리를 초기 위치로 전달해도 시스템 파일 선택기는 접근 가능한 위치로 돌아갔습니다.
- 시스템 파일 선택기의 `Android` 아래에는 `media`만 보였고, `data`와 `obb`는 보이지 않았습니다. 파일 선택/폴더 선택 두 경로 모두 확인했습니다.
- 삼성 내 파일은 `data` 항목을 표시하지만 열면 다음 안내가 나왔습니다.

> Android 제한으로 이 폴더의 내용은 PC에서만 확인할 수 있습니다.

따라서 **일반 파일 편집 APK는 가능하지만, 이 기기에서 Home Up 백업까지 수동으로 주고받는 폰 단독 경로는 확인하지 못했습니다.** 권한 없는 APK 하나로 이미 해결했다고 소개할 수 없습니다.

ADB는 시험 앱 설치·화면 조작·앱 내부 진단 결과 확인·시험 후 정리에 사용했습니다. APK의 파일 읽기·쓰기를 ADB로 대신하거나 권한을 부여하지 않았습니다. 시험 앱과 가상 파일은 제거했고 Home Up 백업 스위치와 화면 제한 시간은 원래 상태로 유지했습니다. 이 파일 입출력 시험에서는 런처 복원을 실행하지 않았습니다.

## 3. 정적 구현에서 확인한 계약

Home Up의 레이아웃 복원은 파일을 런처에 넘기는 전체 복원 경로입니다. 별도 Apps-only 복원 옵션은 확인하지 못했습니다. 파일명 숫자를 시간으로 강제 검증한다는 근거도 없어, 숫자형 새 파일명은 호환되는 관례로 사용할 뿐 필수 프로토콜로 단정하지 않습니다.

Home Up 설정을 복원하는 Smart Switch 브로드캐스트와 런처 레이아웃 EXML은 서로 다른 경로입니다. 일반 APK가 삼성 내부 권한을 얻는다고 가정하거나, 유사한 브로드캐스트가 있다는 이유만으로 백업/복원을 직접 호출할 수 있다고 주장하지 않습니다.

## 후속 과제

- 사용자 승인 아래 APK 내장 무선 ADB 또는 선택적 Shizuku 파일 전송 경로 실기기 검증
- 휴먼리더블 앱 이름·아이콘, 분류안 편집 UI
- 폴더 밖 앱 유지와 숨긴 앱의 명시적 보존 모델
- 추가 Home Up/One UI 버전별 합성 회귀 입력과 실제 복원 검증

각 과제는 아직 구현·검증하지 않았습니다. 현재 APK가 자동 분류나 순정 폴더 편집을 제공하는 것으로 오해하지 마세요.
